# Feeds & Speeds — native

A **fully native** iOS (and Android) feeds & speeds calculator, plus its
backend, in **one codebase**. The app is React Native (Expo); the backend is
Next.js on Vercel; all the machining math lives in a shared TypeScript package
used by both. No webview — real native screens.

```
feeds-speeds-native/
├── packages/core/     @feedspeed/core — framework-free machining logic
│                      (types, reference tables, the feeds & speeds engine:
│                      RPM from surface speed, feed from chip load / feed-per-
│                      rev, depth & width of cut, MRR, spindle-power & torque,
│                      tool-deflection estimate, radial chip thinning).
│                      Shared by BOTH the app and the API. Fully unit-tested.
├── apps/mobile/       Expo + Expo Router — the native app (Calculator, My
│                      Tools, Reference, Settings). Presets stored on-device.
└── apps/api/          Next.js API routes — /api/calc (compute with the shared
                       core), /api/reference (option catalog), /api/health.
                       Deploys to Vercel (+ Postgres later for cloud sync).
```

> The self-contained web version lives at `../feeds-speeds/` and stays the
> quick, no-install option. This native build is the publishable app.

## What makes it more than a chart

Most free calculators just do RPM and feed. This one is **machine-aware**:

- **Spindle-power check** — estimates the horsepower the cut needs
  (`MRR × unit-power ÷ efficiency`) and warns when it exceeds your machine's
  available power. A mini-mill and a Haas get different advice.
- **Tool-deflection estimate** — enter tool stick-out and it models the cutter
  as a cantilever beam (`Ft·L³ / 3EI`) to flag when a long, thin end mill will
  push off and lose accuracy.
- **Adaptive / HSM mode** — light radial, deep axial, with radial chip thinning
  applied the way real CAM does.
- **Tool-life & cost estimate** — the extended Taylor equation turns cutting
  speed, feed per tooth, axial depth and radial engagement into expected tool
  life, then a shop rate, tool price and optional volume give $/volume, cycle
  time, per-job cost and how many tools a job burns.
- **Coating-aware** — pick TiN / TiCN / AlTiN / ZrN / diamond and tool life
  adjusts, *by material*: AlTiN rewards hot ferrous work but not aluminium, and
  diamond is flagged (and penalised) if you point it at steel.
- **It learns from your shop** — log how a cut actually went (broke / dulled /
  as expected / lasted great) and the tool-life estimate for that material is
  nudged toward what you really see, on-device.
- **Ball-nose finish** — for a ball-nose tool, solve surface finish either way:
  a target scallop (cusp) height ↔ the stepover that gives it, with a plain-
  English finish grade (mirror → needs finishing).
- **Tapping** — pick a standard thread (metric / UNC / UNF) or a custom size and
  get the tap-drill diameter for your chosen % thread, the tapping RPM, and the
  feed **locked to the pitch** (one pitch per rev, as it must be), plus rigid-
  tapping / fluid / chip-clearing guidance.
- **Your tool crib** — save the tools you actually own (coating, flutes, price)
  and one-tap load them. Save dialed-in jobs per material + operation.
- **Shop packs** — export your whole setup (tool crib, saved jobs, learned
  calibrations, defaults) as one JSON file to back up, move phones, or hand to a
  shop mate; importing merges it in. File-based and offline — nothing leaves the
  device unless you share the file.
- **Imperial or metric** everywhere, offline-first, no login, no paywall.

See [`IDEAS.md`](./IDEAS.md) for the longer roadmap (chatter detection via the
mic, G-code export, a community "what actually worked" dataset).

## Prerequisites

- **Node 20+** and npm.
- A **Mac with Xcode** *or* an **Expo EAS** account (EAS builds iOS in the
  cloud — no Mac required).
- An **Apple Developer Program** membership ($99/yr) to submit to the App Store.

## Install & run

```bash
npm install                 # installs all workspaces
npm test                    # runs the @feedspeed/core unit tests
npm run typecheck           # typechecks core + mobile + api

# Native app (Metro + Expo dev server)
npm run mobile              # then press i for the iOS simulator, or scan the QR

# Backend API (local)
npm run api                 # Next.js on http://localhost:3002
```

`npx expo install` inside `apps/mobile` reconciles native module versions with
the installed Expo SDK if you change any.

## Build for the App Store (Expo EAS)

```bash
cd apps/mobile
npm i -g eas-cli
eas login
eas build:configure
eas build --platform ios --profile production   # cloud build → .ipa
eas submit --platform ios                        # upload to App Store Connect
```

Set the bundle identifier (`com.foldyfamily.feedspeed`) and version in
`app.json`. Icons/splash are generated by `node assets/gen-assets.mjs`.

## Deploy the API (Vercel)

Create a Vercel project with **Root Directory** set to `apps/api`. No database
is required for the calculator; attach Vercel Postgres later to enable cloud
sync of tool cribs and jobs (`POSTGRES_URL` — see `apps/api/.env.example`). Point
the app at it via `expo.extra.apiBaseUrl` in `apps/mobile/app.json`.

## The math (starting points, not guarantees)

Every number is a conservative starting point from common machinist references.
Coating, stick-out, work holding, coolant and machine condition all shift real
results. Start on the safe side, trust your ears and your chips, and defer to
the tool manufacturer's data.
```
RPM        = (SFM × 12) / (π × D)
Feed       = RPM × chip load × flutes        (drills: RPM × feed-per-rev)
MRR        = Ap × Ae × feed
Power (hp) = MRR × unit-power / efficiency
Deflection = Ft × L³ / (3 × E × I)           (cantilever, end-load estimate)
Tool life  = Tref × (Vref/V)^(1/n) × (Fref/F)^fe × (Dref/Ap)^de × (Aeref/Ae)^ee
             × coating multiplier × your learned calibration
Cost/vol   = (machine $/min + tool $/min) / MRR
```
