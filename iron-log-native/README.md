# Iron Log — native

A **fully native** iOS (and Android) build of Iron Log, plus its backend, in
**one codebase**. The app is React Native (Expo); the backend is Next.js on
Vercel; all the training logic lives in a shared TypeScript package used by
both. No webview — real native screens.

```
iron-log-native/
├── packages/core/     @ironlog/core — framework-free training logic
│                      (types, dates, e1RM, double progression, weekly volume
│                      landmarks, mesocycle/deload, progression plan + lagging
│                      flags, analytics, starter split, movement library).
│                      Shared by BOTH the app and the API. Fully unit-tested.
├── apps/mobile/       Expo + Expo Router — the native app (Today, Progress,
│                      Split, People, Ranks). Data in on-device SQLite.
└── apps/api/          Next.js API routes — auth, cloud sync, People/Ranks,
                       feed, groups. Deploys to Vercel + Postgres.
```

> The original PWA still lives at `../iron-log/` and stays the shipping app
> until this native build reaches feature parity. This is the migration target,
> not a second product — once parity lands, the PWA can be retired.

## Prerequisites

- **Node 20+** and npm.
- A **Mac with Xcode** *or* an **Expo EAS** account (EAS builds iOS in the cloud
  — no Mac required).
- An **Apple Developer Program** membership ($99/yr) to submit to the App Store.

## Install & run

```bash
npm install                 # installs all workspaces
npm test                    # runs the @ironlog/core unit tests

# Native app (Metro + Expo dev server)
npm run mobile              # then press i for the iOS simulator, or scan the QR

# Backend API (local)
npm run api                 # Next.js on http://localhost:3001
```

`npx expo install` inside `apps/mobile` reconciles native module versions with
the installed Expo SDK if you change any.

## Build for the App Store (Expo EAS)

```bash
cd apps/mobile
npm i -g eas-cli
eas login
eas build:configure
eas build --platform ios --profile production   # cloud build → .ipa
eas submit --platform ios                        # upload to App Store Connect
```

Set the bundle identifier (`com.foldyfamily.ironlog`) and version in
`app.json`. Icons/splash are generated by `node assets/gen-assets.mjs`.

**App Store note (guideline 4.2):** a training app benefits from real native
value — the roadmap adds **HealthKit** (write workouts, sync bodyweight),
haptics (already wired on set completion) and notifications, which is what keeps
this from reading as "just a wrapped website."

## Deploy the API (Vercel)

1. Import `apps/api` as a Vercel project (root directory `apps/api`).
2. Add a **Postgres** store (Vercel Postgres / Neon) — `POSTGRES_URL` is injected.
3. Set `AUTH_SECRET` to a long random string (`openssl rand -hex 32`).
4. Run `apps/api/schema.sql` against the database once.
5. Point the app at it: `app.json → expo.extra.apiBaseUrl`.

The app is **fully functional offline without the API** — accounts, People,
Ranks, feed and groups light up once the API is deployed and you sign in.
